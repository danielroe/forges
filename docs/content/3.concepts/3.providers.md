This page explains how you create a provider and what every provider contains.

## Factories

Functions such as `github()` don't create a provider right away. They return a factory, which holds the options you passed and builds the provider when you call `create()`. No request goes out until you call a method on the provider.

```ts
import { github } from 'forges/github'

const factory = github({
  auth: { type: 'token', token: process.env.GITHUB_TOKEN! },
})
const gh = factory.create()
```

Splitting the work in two steps lets you describe your providers in one place and build them where you need them. `createForges()` relies on this too. It accepts factories and calls `create()` on each one.

## The provider interface

Every provider has the same shape, whichever forge it talks to. It has `forge`, `instance`, `baseUrl` and `capabilities`, along with namespaces for the operations: `repos`, `threads`, `notifications`, `checks`, `ci`, `contents`, `releases`, `webhooks`, `search`, `securityAlerts`, `installations`, `users` and `sources`. Reviews live on `threads`. The [provider reference](/reference/provider) lists everything in them.

All of the namespaces exist on all of the providers. If a forge lacks an operation, the method is still there and rejects when you call it, which means TypeScript doesn't force you to cast at every call site. To find out whether an operation will work, use [`can()`](/guides/capabilities) at run time.

## Escape hatch

The model doesn't cover every endpoint of every forge. When you need one that it doesn't, `provider.request()` lets you call it directly. It sends a request to an endpoint relative to `baseUrl`, or to an absolute HTTP(S) URL, and applies the provider's authentication, user agent, timeout and error mapping, just as it does for its own calls.

If you send a request to a different origin, the provider leaves out its credentials and default headers, so a token for one host is never sent to another.

## Subpath exports

Each provider has a subpath of its own, such as `forges/gitlab`, and the root entry re-exports all of them. The package declares `sideEffects: false`, so a bundler drops the providers you don't use from either entry. A server build that copies dependencies instead of bundling them copies every provider for the root entry and only one for a subpath. See [Server builds](/guides/bundling#server-builds).

## Writing your own

If you need a forge that `forges` doesn't support, a provider is a single call to `defineForgeProvider()`. See [Write a provider](/contributing/write-a-provider) to learn how.
