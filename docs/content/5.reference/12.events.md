Every provider lists the kinds and actions that its webhook deliveries translate into in `webhooks.events`, and the matrix on this page is built from that list. If you want to know what an event looks like, read [Events](/concepts/events). The following example checks whether a provider can deliver label events:

```ts
const labels = provider.webhooks.events.some(
  event => event.kind === 'label' && event.action === 'labelled',
)
```

The matrix covers webhook deliveries. Events from `threads.events()` and `sources.subscribe()` use the same kinds, but providers don't list which ones they produce. A kind that is declared without an action, shown as `any`, can arrive with any action, including `other`. Whatever the kind, `kindRaw` and `actionRaw` always keep the names that the forge itself uses.

## Detail and native events

`detail.type` tells you which fields an event carries, so narrowing on it gives you a typed `detail`. The `repo` kind has a separate detail type for each kind of change. An event whose kind has no detail type has no `detail` at all.

When you register a webhook, `webhooks.create({ events })` translates each kind into the event names of the forge, and `webhook.events` maps them back again. If you need a forge event that has no kind, subscribe to it by name with `nativeEvents`. The following table lists the detail type and fields of each kind:
