`forges` describes its model with JSON Schemas, so that data you stored as JSON can be checked, and so that languages other than TypeScript can generate the same types. The schemas follow the types in the source.

## Use the schemas in code

`forges/schema` exports `schemas`, an object keyed by type name. References between schemas use the OpenAPI form `#/components/schemas/<Type>`, so `schemas` can be used as the `components.schemas` of an OpenAPI document.

```ts
import { schemas } from 'forges/schema'

// { type: 'object', properties: { ref: ..., kind: ... }, required: [...] }
schemas.Thread
```

## Use the schemas as files

`forges/schema/<Type>.json` is one type as a standalone [draft-07](https://json-schema.org/draft-07) document. It carries the definitions it references, so a validator needs nothing else.

```ts
import Ajv from 'ajv'
import { reviveDates } from 'forges'
import thread from 'forges/schema/Thread.json' with { type: 'json' }

const validate = new Ajv({ strict: false, validateFormats: false }).compile(thread)

const stored = JSON.parse(text)
if (!validate(stored)) {
  throw new Error('Not a Thread')
}

// JSON has no dates, so turn the ISO strings back into `Date`s.
const value = reviveDates(stored)
```

## What the schemas say

- `Date` fields are `{ type: 'string', format: 'date-time' }`. Use [`reviveDates()`](/reference/data-model#revivedates) to turn them back into dates.
- `Uint8Array` fields, such as the content of a binary file, are described by a note and `x-forges-type: Uint8Array`, because JSON cannot carry bytes.
- `raw` and `payload` fields accept anything. They hold the forge's own response.
- Objects accept extra properties, so a newer version of `forges` can add a field without breaking stored data.
- Every schema has an `x-forges-type` with the name of the type.
