The Pushin.eu provider works with [Pushin.eu](https://pushin.eu), a European Git host whose API is modelled on GitHub's. It can read repositories, labels, collaborators, teams, issues, pull requests, comments, reviews, notifications and releases. It can also create issues, pull requests, comments, labels and releases, add collaborators, reply to review comments, and resolve review threads. The [OpenAPI specification](https://pushin.eu/api/v1/openapi.json) of the API documents its endpoints.

## Authentication

The provider accepts a personal access token, which you create in your Pushin.eu settings. These tokens start with `pun_pat_` and aren't scoped to specific resources. The provider sends the token in an `Authorization: Bearer <token>` header:

```ts
import { pushin } from 'forges/pushin'

const forge = pushin({
  auth: { type: 'token', token: process.env.PUSHIN_TOKEN! },
})
```

If you leave out `auth`, the provider reads public repositories anonymously.

## Instance

The `baseUrl` defaults to `https://pushin.eu`, and the provider appends `/api/v1` itself.

## Issues and pull requests

`threads.get()` reads both issues and pull requests, and `threads.comments()` reads the comments on both. `threads.list()` lists both kinds by default. To select only one, set `kind: 'issue'` or `kind: 'pull_request'`.

`threads.create()` opens both kinds. A pull request needs `head` and `base`, and `labels` must name labels that already exist. The API doesn't set assignees on a new thread, so `threads.create()` rejects `assignees`. The API has no endpoints for editing, closing or reopening a thread, or for editing or deleting a comment, so the provider doesn't support them.

Listings use `Link` pagination, and they include rate-limit information from the headers of the response.

## Reviews

`threads.reviews()` and `threads.getReview()` read the reviews of a pull request, with their inline comments. A review thread's id is the id of its first comment, which is what `threads.resolveReviewThread()` and `threads.unresolveReviewThread()` take. Reviews are created and submitted in the web interface only, so `threads.createReview()` isn't available.

## Collaborators

The API grants `pull`, `push` and `admin` permissions only. `repos.addCollaborator()` grants `push` for `maintain` and `pull` for `triage`, and rejects `none`. The collaborator has access immediately, without an invitation.

## Notifications

`notifications.list()` reads the notifications of the authenticated account. Set `all: true` to include notifications that have been read, or `since` to filter by the time of the activity. The provider doesn't support changing notifications.

## Thread events

The API has no timeline, so the provider can't list the events of a thread directly. Instead, `threads.events()` is `'emulated'` from the comment listing, which means it returns comment events only.

## Labels

When the API supplies a six-digit hex colour for a label, `Label.colour` contains it. If the API uses a named colour such as `purple`, `Label.colour` stays unset.

## Accounts

The API only reads the authenticated account, so `users.get(login)` isn't available.

## Releases

Pushin.eu doesn't create tags for releases. `releases.create()` stores `target` on the release but doesn't tag that commit, so you need to push the tag before you publish a release. If the tag doesn't exist, the API rejects a published release, so you can only create a draft. `releases.update()` changes the stored `target` in the same way, without moving the tag.

`release.assets` only includes assets that have finished uploading. An asset that is still uploading has no download URL, so it is left out.

## Webhooks

The API has no endpoints for hooks and no documented signature scheme. For this reason, `capabilities.webhooks.ingest` is `'not_applicable'`, and the provider doesn't verify or translate deliveries.
