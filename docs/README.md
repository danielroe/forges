# forges docs

This is the documentation site for `forges`, built with [Docus](https://docus.dev). You can work on it with these commands:

```sh
pnpm dev:docs
pnpm build:docs
pnpm test:docs
```

## How the site is put together

- `content/` holds the pages, grouped as getting started, guides, concepts, providers, reference, examples and contributing.
- `content/index.md` renders the landing page from `app/components/content/LandingPage.vue`, and the parts of that page live in `app/components/landing/`.
- `app/components/app/AppHeaderContent.vue` is a copy of the Docus header with an added link to npmx, and `app/components/app/AppFooterContent.vue` replaces the Docus footer. To keep the first load light, `AppHeader.vue` hydrates the header when the browser is idle, and `AppFooter.vue` hydrates the footer once it scrolls into view.
- `content/developers.md` is the developer portal at `/developers`. It sets `navigation: false`, which keeps it out of the sidebar.
- `server/mcp/resources/` holds the MCP resources that are served at `/mcp`, next to the `list-pages` and `get-page` tools from Docus.

## Tests

The tests in `test/` run against the build in `.output`, so build the docs before you run them. They run as the `docs` project in the `vitest.config.ts` at the root of the repository.

## Generated text

Text between `<!-- <marker>:start -->` and `<!-- <marker>:end -->` comments is generated by the files in `scripts/sections/`. After you change a provider, run `pnpm capability-matrix` from the root of the repository to update it. When the generated Markdown contains a table, the table is wrapped in a component such as `::capability-matrix`. The component renders the same data from `#capabilities`, and the table stays in the raw Markdown so that search and agents can read it.
