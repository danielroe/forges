# pushin.eu

The pushin.eu provider covers [pushin.eu](https://pushin.eu), a European git host with an API modelled on GitHub's. The API serves repositories, labels, collaborators, pull requests, and comments. The provider covers those resources and reports every other capability as `false`.

> [!NOTE]
> The pushin.eu provider is experimental.

## Authentication

The provider accepts a personal access token that you create in your pushin.eu settings. Tokens start with `pun_pat_` and aren't scoped to specific resources. The provider sends the token in an `Authorization: Bearer <token>` header:

```ts
import { pushin } from 'forges/pushin'

const forge = pushin({ auth: { type: 'token', token: process.env.PUSHIN_TOKEN! } }).create()
```

Without `auth`, the provider reads public repositories anonymously.

## Instance

`baseUrl` defaults to `https://pushin.eu`, and the provider appends `/api/v1`.

## Pull requests only

The API has no issue endpoints, so `threads.get()` and `threads.list()` return pull requests only. `threads.comments()` reads comments on both issues and pull requests.

## Thread events

The API has no timeline. `threads.events()` is `'emulated'` from the comment listing, and returns comment events only.

## Labels

Label colours are names, such as `purple`, and not hex values. `Label.colour` is unset.

## Accounts

The API reads only the authenticated account, so `users.get(login)` is unavailable.

## Webhooks

The API has no hook endpoints and no documented signature scheme. `capabilities.sources.webhook` is `false`, and the provider doesn't verify or translate deliveries.

`pushin()` contains no webhook code, so the provider has no `pushinLite()` factory.

## Recording fixtures

```sh
PUSHIN_TOKEN=... FIXTURE_PUSHIN_REPO=pjullrich/pushin pnpm record-fixtures pushin
```

To choose the threads to record, set `FIXTURE_PUSHIN_ISSUE` and `FIXTURE_PUSHIN_PULL`. To record another deployment, set `PUSHIN_BASE_URL`. The recorder redacts `pun_pat_` tokens.
